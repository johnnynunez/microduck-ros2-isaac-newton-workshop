# MicroDuck: ROS 2, reinforcement learning and physical-AI agents

## User-approved requirements

Build and publish a public workshop project on `johnnynunez`'s personal GitHub for the ROSCon España 2026 session **Integración de RL en ROS 2 con Microduck: de la simulación al juego**, 27 October 2026, 15:00–17:00, Aula 2-7, Valencia.

- Two hours, including the instructor's opening slides about NVIDIA technologies and Newton.
- Introduce ROS 2, NVIDIA Isaac ROS **5.0**, Isaac Sim **6.2.0** and Isaac Lab **3.0** using Pollen Robotics MicroDuck.
- **Newton physics only**. MJLab is upstream training reference material, not an Isaac Lab implementation or a replacement runtime. PhysX is not a fallback.
- Participants use **NVIDIA Brev**, with instructor-provided credits for one day on **L40S or RTX PRO** instances.
- Finish by implementing a real ROS/perception integration in **CASCADE**, an agentic physical-AI orchestrator, and controlling the simulated robot through a real local agent.
- Public upstream sources: https://github.com/pollen-robotics/microduck and https://github.com/pollen-robotics/microduck_rl .
- Publication is authorized. Provisioning paid cloud instances, changing credit allocations, and operating physical robots are not part of this implementation.

## Implementation decisions

These are engineering decisions, not claims that the instructor supplied every detail.

1. Use Ubuntu 24.04/Noble and Python 3.12 for the reproducible environment. Isaac ROS 5.0 provides ROS 2 **Lyrical** packages for Noble through NVIDIA's buildfarm. Do not substitute Jazzy/Isaac ROS 4.6, or teach removed NITROS package APIs as current 5.0 APIs.
2. Prepare images, source pins, assets and models before class. Each participant works inside their own Brev instance through SSH/VS Code and a forwarded browser preview. No local laptop GPU is required.
3. One canonical public MicroDuck per interactive simulation; vectorized environments are for the training exercise. No private Creative/NVIDIA assets, private policies or machine credentials enter this repository.
4. Isaac Lab owns the Newton model. Read the Lab articulation, actuator and actual IMU/camera APIs. Do not initialize a second Sim-native physics owner or assume prim readers see Lab's Newton model.
5. Prefer an explicit ROS 2 Lyrical adapter for the Lab-owned model. If Python/ROS ABI isolation requires a sidecar, document the boundary and transport honestly. Ordinary CPU ROS image publication is not GPU zero-copy; Isaac ROS 5.0's accelerated graph uses the supported `rosidl::Buffer` architecture.
6. Use Pollen's public VelStand v8 ONNX as a **candidate** inference baseline, with exact joint order, observation/action convention and actuator provenance. Walking, zero-command balance and resume must be tested on Newton before calling the capstone ready. Preserve upstream training/deployment discrepancies rather than silently claiming parity.
7. The RL exercise runs a real Isaac Lab/Newton environment and a short real optimizer update. Do not promise a converged gait trained from scratch in twenty minutes. A public ONNX is not a PPO optimizer/critic checkpoint; teacher checkpoints are not assumed available.
8. The capstone game reads a visual signal through real onboard rendered RGB and actual Isaac ROS AprilTag detection, then lets the local CASCADE agent choose a short bounded body-velocity action. No simulator object poses, perfect odometry, external overview localization or synthetic detector fallback may enter the agent.
9. A single simulation thread owns actuation. Use explicit command identities, episode/generation checks, finite bounds, expiry, a wall-clock watchdog and priority stop. The model cannot re-arm an emergency stop. Acknowledgment and physical verification are separate statuses.
10. Keep reference solutions complete and runnable; student exercise TODOs live separately and fail explicitly until implemented. CPU fixtures are not live ROS, physics or LLM evidence.

## Proposed 120-minute route

- 00–15: instructor technology overview and Newton physics.
- 15–35: ROS 2 nodes, topics, messages, parameters, QoS and simulation clock using MicroDuck telemetry.
- 35–55: launch Isaac Sim 6.2 / Isaac Lab 3 with Newton; inspect the robot and real sensor streams.
- 55–75: observations, actions and rewards; run a short RL training experiment and load a separately validated policy.
- 75–90: Isaac ROS 5.0 accelerated AprilTag perception from actual images.
- 90–115: implement CASCADE observation and bounded-motion tools; run the perception-driven agent game.
- 115–120: recap, next experiments and cloud-instance shutdown checklist.

## Acceptance

1. Public GitHub repository has actual code, bounded setup/preflight, student instructions, reference solutions, tests and a 120-minute instructor runbook.
2. CPU tests exercise malformed/nonfinite commands, freshness, epoch/generation, stop races, provenance hashes, policy shape/order and model-input redaction.
3. Real runtime receipt identifies the actual imported Sim/Lab/Newton versions and the authoritative Newton model. Reset/step and a short RL optimizer update are executed, not just imported.
4. Real ROS graph carries clock, encoder/IMU data and calibrated onboard images. Isaac ROS 5.0 produces detections from images; no stand-in detection publisher is counted as success.
5. Real local CASCADE model chooses observation and motion tools; the resulting command reaches the learned policy/Newton model and is independently verified. Stop and stale-command failures remain visible.
6. Actual test provenance and limits are published: local RTX PRO validation is not a Brev-instance or L40S execution receipt. Cloud rehearsal remains separately identified unless it is actually run.
7. No cloud costs or physical actuation are triggered by publishing or by default setup. Teardown distinguishes stopping containers from stopping/deleting the Brev instance and ending billing.
